    1 绪论¶

    1.1 因特网概述¶

    1.1.1 网络、互连网（互联网）和因特网¶

    • 网络（Network)）由若干结点（Node）和连接这些结点的链路（Link）组成。

    • 多个网络还可以通过路由器互连起来，这样就构成了一个覆盖范围更大的网络，即互联网。因此，互联网是“网络的网络（Netwrok of Networks）”

    • 因特网（Internet）是世界上最大的互连网络（用户数以亿计，互连的网络数以百万计）。

    1.1.3 因特网服务提供者 Internet Service Provider¶

    基于ISP的三层结构的因特网：

    一个ISP可以很方便地在因特网拓扑上增添新的层次和分支。三层结构仅为示意。

    • 第一层ISP：通常也被称为因特网主干网，覆盖国际性区域；拥有高速链路和交换设备；第一层ISP之间直接互连；服务面积最大。（在中国是移动、联通、电信）
    • 第二层ISP和大公司：第一层ISP的用户，区域性或国家性覆盖规模，与少数第一层ISP相连接。
    • 第三层ISP：第二层ISP的用户，只拥有本地范围的网络。一般的校园网、企业网、住宅用户、无线移动用户都是第三层ISP的用户。

    1.1.4 因特网的标准化工作（了解即可）¶

    因特网的标准化工作对因特网的发展起到了非常重要的作用。

    因特网在制定其标准上的一个很大的特点是面向公众。

    因特网所有的RFC（Request For Comments）技术文档都可从因特网上免费下载。任何人都可以随时用电子邮件发表对某个文档的意见或建议。

    因特网协会ISOC是一个国际性组织，它负责对因特网进行全面管理，以及在世界范围内促进其发展和使用：

    层级：ISOC > IAB > IETF = IRTF

    • 因特网体系结构委员会IAB，负责管理因特网有关协议的开发

    • 因特网工程部IETF，负责研究中短期工程问题，主要针对协议的开发和标准化

    • 因特网研究部IRTF，从事理论方面的研究和开发一些需要长期考虑的问题。

    制订因特网的正式标准要经过以下4个阶段：

    注：不是所有的RFC文档都能成为因特网标准，只有一小部分可以。

    1. 因特网草案（在这个阶段还不是RFC文档）
    2. 建议标准（从这个阶段开始就成为RFC文档）
    3. 草案标准
    4. 因特网标准

    1.1.5 因特网的组成¶

    从功能上看，可划分为边缘部分和核心部分。

    边缘部分：由所有连接在因特网上的主机（可以是台式电脑、大型服务器、笔记本、平板、智能机、智能表、物联网智能硬件如智能摄像头等）组成。这部分是用户直接使用的，用来进行通信（传送数据、音频或视频）和资源共享。

    核心部分：由大量网络和连接这些网络的路由器组成。这部分是为边缘部分提供服务的（提供连通性和交换）。

    在核心部分起特殊作用的是路由器，它是一种特殊的计算机，但不被称为主机。

    路由器是实现分组交换的关键构件，其任务是转发收到的分组，这是网络核心部分最重要的功能。

    1.2 三种交换方式：电路交换、报文交换和分组交换¶

    从通信资源的分配角度来看，交换就是按照某种方式动态地分配传输线路的资源。

    #### 1.2.1 电路交换（Circuit Switching） 电路交换是一种在通信双方之间建立一条专用的物理通路的技术。在数据传输之前，必须先在发送方和接收方之间建立一条端到端的连接，这条连接在整个通信过程中被独占使用。 **过程：** - **连接建立 (Connection Establishment):** 在通信开始前，源节点向目标节点发起连接请求，网络中的交换节点会协同工作，为本次通信预留一条物理传输路径（分配通信资源）。 - **数据传输 (Data Transfer):** 一旦连接建立，数据便沿着这条预留的路径以连续流的形式进行传输。由于路径是专用的，因此数据传输的顺序和时延可以得到保证（一直占用通信资源）。 - **连接释放 (Connection Release):** 通信结束后，连接将被释放，之前占用的资源可以被其他通信所使用（归还通信资源）。 **特性:** - **独占性:** 一旦电路建立，该路径上的带宽资源便被该通信独占，即使没有数据传输，其他用户也无法使用。 - **确定性:** 由于存在预先建立的专用路径，数据传输具有确定的时延和带宽，服务质量 (QoS) 相对有保障。 - **低效性:** 在通信过程中，如果出现静默期（没有数据传输），预留的带宽资源将被浪费。 - **连接建立时延:** 在开始数据传输之前，需要花费一定的时间来建立连接。 **典型应用:** 公共交换电话网络 (Public Switched Telephone Network, PSTN) 是电路交换的典型应用。 #### 1.2.2 报文交换（Message Switching） 报文交换是一种将整个待发送的信息（报文）作为一个完整的单元在网络中进行传输的技术。中间的交换节点采用存储-转发 (store-and-forward) 的方式处理报文。 **过程:** - **报文传输:** 发送端将完整的报文发送到第一个交换节点。 - **存储-转发:** 中间的每个交换节点接收到完整的报文后，会先将其存储在本地，然后根据报文中的目标地址选择合适的输出链路进行转发，直到报文到达目标节点。 **特性:** - **无需预先建立连接:** 在发送报文之前不需要建立专用的连接。 - **存储-转发延迟:** 由于每个中间节点都需要先存储整个报文，然后再转发，因此传输延迟相对较大，尤其对于较长的报文。 - **线路利用率高:** 多个用户可以共享网络资源。 - **适用于低速、容忍时延的应用:** 报文交换更适合于对实时性要求不高，但需要保证报文完整性的应用。 **典型应用:** 早期的一些电报系统以及某些早期的电子邮件系统曾采用报文交换。但在现代网络中，由于其较大的延迟，报文交换已较少使用，更多地被分组交换所取代。 #### 1.2.3 分组交换（Packet Switching） 分组交换是一种将待发送的数据分割成若干个较小的数据块，称为分组（packets），每个分组独立地在网络中进行路由和传输的技术。 > 发送方：构造分组，发送分组 > > 路由器：缓存分组，转发分组 > > 接收方：接受分组，还原报文 **过程:** - **数据分段 (Segmentation):** 发送端将待发送的数据分割成一个个带有控制信息（如源地址、目标地址、序号等）的分组。 - **分组转发 (Forwarding):** 每个分组在网络中的交换节点（路由器）处，根据其目标地址选择合适的路径进行转发。不同的分组可能经过不同的路径。 - **分组重组 (Reassembly):** 接收端接收到所有的分组后，根据分组中的序号等信息，将它们重新组装成原始的数据。 **关于数据分段和报头的表格概括：** | 特征 | 数据分段 (Data Segmentation) | 分组头 (Header) | | ----------------------------------------- | ------------------------------------------------------------ | ------------------------------------------------------------ | | **目的 (Purpose)** | 将大数据单元分割成小块，便于网络传输和管理；适应链路的 MTU限制。 | 包含控制信息，使分组能够在网络中被正确地路由、传输、排序和重组；提供协议所需的功能（如可靠性、服务质量等）。 | | **过程 (Process)** | 1. 确定最大传输单元 (MTU)。
    2. 传输层协议（如 TCP、UDP）对应用数据进行逻辑划分。
    3. 每个数据块添加报头。 | 在每个数据块的前面（有时也会有尾部）添加包含控制信息的字段。不同的协议层添加不同的报头信息。 | | **关键参与者 (Key Players)** | 传输层协议 (TCP, UDP)；网络层协议 (IP) 在确定分片时也相关。 | 各个协议层：
    - 网络层 (例如，IP)
    - 传输层 (例如，TCP, UDP)
    - (有时) 数据链路层（例如，以太网帧头） | | **报头常见内容 (Common Header Contents)** | N/A (此为过程) | **网络层 (IP报头):** 源/目标IP地址、协议类型、生存时间 (TTL)、首部校验和、标识、标志、片偏移等。
    **传输层 (TCP报头):** 源/目标端口号、序号、确认号、控制位、窗口大小、校验和等。
    **传输层 (UDP报头):** 源/目标端口号、长度、校验和等。 | | **重要性 (Importance)** | 提高网络利用率；方便错误检测和重传（通常在分组级别进行）；允许不同大小网络之间的互联。 | 实现分组的寻址和路由；提供可靠性机制（如TCP的序号和确认）；标识上层协议；进行错误检测；支持服务质量等。 | **特性:** - **高效性:** 网络资源可以被多个用户共享，提高了带宽的利用率。当某个用户没有数据发送时，其占用的资源可以被其他用户使用。 - **灵活性:** 分组可以根据网络拥塞情况动态选择传输路径，提高了网络的鲁棒性。 - **可变时延和抖动:** 由于分组在网络中独立路由，其传输路径和经历的拥塞程度可能不同，导致到达接收端的时延和时延变化（抖动）可能较大。 - **开销:** 每个分组都需要附加额外的头部信息，增加了传输的开销。 **典型应用:** 互联网 (Internet) 采用的是分组交换技术，如TCP/IP协议族（后续会具体展开）。 ★分组交换有虚电路和数据报两种方式： | 特征 | 虚电路 (Virtual Circuit) | 数据报 (Datagram) | | ------------------ | ------------------------------------------------------------ | ------------------------------------------------------------ | | **连接性** | 面向连接 (Connection-Oriented)：需要在数据传输前建立逻辑连接。 | 无连接 (Connectionless)：每个分组独立传输，无需预先建立连接。 | | **路由选择** | 在虚电路建立阶段确定路径，同一会话的所有分组都沿着这条预定路径传输。 | 每个分组在网络中独立进行路由选择，路径可能不同。 | | **分组顺序** | 通常能够按发送顺序到达接收方，网络负责维护分组的顺序。 | 分组可能乱序到达接收方，接收端需要进行重组。 | | **每分组报头开销** | 较低：在数据传输阶段，每个分组只需要携带较短的虚电路标识符 (VCI/VPI)。 | 较高：每个分组都需要携带完整的源地址和目标地址信息。 | | **网络可靠性** | 依赖于虚电路路径的稳定性。如果虚电路中的某个节点或链路发生故障，则整个连接会中断。 | 更具鲁棒性：如果网络中某个节点或链路发生故障，后续分组可以动态选择其他可用路径。 | | **连接建立时间** | 需要花费一定的时间来建立虚电路。 | 不需要连接建立时间，可以立即发送分组。 | | **网络节点角色** | 交换节点在虚电路建立和释放过程中需要维护虚电路的状态信息（例如，虚电路标识符与端口的映射关系）。在数据传输过程中，根据虚电路标识符进行快速转发。 | 路由器根据每个分组的目标地址进行路由决策，不维护会话状态信息。 | | **资源预留** | 某些虚电路技术（如ATM）支持在连接建立时预留带宽等资源，以保证服务质量。 | 通常不支持资源预留，网络资源是尽力而为地分配给每个分组。 | | **错误处理** | 网络可以在虚电路层面提供一定的错误检测和纠正机制。 | 错误检测通常在数据链路层和传输层进行，网络层本身不提供可靠传输。 | | **拥塞控制** | 网络可以在虚电路层面实现拥塞控制机制，例如通过反压等方式。 | 拥塞控制通常由上层协议（如TCP）负责，网络层仅提供拥塞指示。 | | **寻址方式** | 在连接建立时使用全局地址，数据传输阶段使用局部虚电路标识符。 | 每个分组都包含全局的源地址和目标地址。 | | **适用场景** | 适用于需要保证数据按序到达、对时延敏感的应用，例如早期的ATM网络。 | 适用于灵活、可扩展的数据通信，例如互联网上的各种应用。 | | **典型应用** | X.25，帧中继 (Frame Relay)，异步传输模式 (ATM)。 | 互联网协议 (IP)。 | ### 1.3 计算机网络的定义和分类 ### 1.4 计算机网络的性能指标
